# M4.1 · 双账号彻查（0.6.0）

日期：2026-10-22 · 版本：`0.6.0-M4` · 起因：用户指出「设置里没有填主人昵称/UID 的地方」

## 0. 为什么会有这次彻查

我在 M0 写配置表时，把它照抄成了「登录账号的 mid/name」，而需求文档 §7.9 又要求「只认 `owner.mid`」。
我把这两个概念合并成了「主人 = 登录账号」，于是所有跟主人有关的功能都建立在错误前提上：

- 评论 @ 用的是登录账号昵称，而那个字段从来没被回填过 → **评论实际上一个 @ 都没带**；
- 私信收件人 = 登录账号 → **宠物号给自己发私信**；
- 双向聊天只认 `senderId === 登录账号` → **主人（另一个号）发来的消息永远不回**。

用户拍板：**必须是两个号，不做回退；主人 UID 是首次配置的必填项。**
所以这次不是「补一个字段」，而是把整个程序按「两个号」重新过一遍。

## 1. 新的模型（唯一口径）

| 角色 | 配置 | 用途 | 不许做什么 |
|---|---|---|---|
| 登录账号（「鲸鲸」） | `account.mid` / `account.name`，登录后自动回填 | 发送方身份（评论区/私信里的 sender）、跳过「自己回自己」、面板显示 | **不许被当成主人** |
| 主人（你） | `account.ownerMid` / `account.ownerName`，**必填**、必须是另一个 UID | 评论 @、私信收件人、聊天鉴权、主人直发 | 缺了/填成登录账号 → 相关功能**明确拒绝**，不回退 |

唯一入口：`src/account/owner.ts` 的 `resolveOwner(config, selfMid)`，返回 `{mid, name, ok, problem}`。
`ok = ownerMid > 0 && ownerMid !== selfMid`；`problem` 是给用户看的一句话（面板/报告/日志都用它）。

## 5. 仍需你本人点一次（我碰不到真账号）

1. **填主人**：面板「账号」页 → 主人 UID（你自己的号）→「按 UID 自动取昵称」→ 保存主人。
2. **看 @ 是否真的 @ 到你**：打开分享开关跑一轮（或点「预演一轮」看文案），确认评论开头是 `@你的昵称`。
3. **私信**：私聊页发一条测试消息，确认手机 B 站收到（收件人应是你，不是鲸鲸）。
4. **聊天**：用你的号给鲸鲸发私信，确认它回你；再用鲸鲸的号给自己发一条，确认它**不回**。
5. **主人直发**（可选）：设置 → 监听与回复 → 打开「主人的回复直接发」，然后在评论里回它一条，观察是否直接回复。

## 6. 遗留风险（说清楚，不藏）

- **主人必须有第二个 B 站号**。只有一个号的话，主人 UID 只能填登录账号本身 → 程序会明确拒绝 @/私信/聊天，而不是悄悄退化成「自己对自己」。
- **昵称自动取依赖 `x/web-interface/card`**（匿名可读）；取不到就手填，不影响其它功能。
- **`ownerDirect` 会把「主人回复」直接发出去**（默认关）。它仍受总写开关、急停、风控冷却、预演、每日写额度约束，但**不再经过你点批准**——开之前请确认你接受这一点。
- **主人在评论区回的评论**（不是私信）与陌生人一样会被监听到；区别只在于标了 `fromOwner` 且（若开着）直接回。
- **评论被 B 站挂起（`state=17`）时的预防措施还没做**：0.6.1 只做到识别（`held`）；文案自检、自动复查、更细节流记在 [`BACKLOG.md`](./BACKLOG.md)，等程序完成、与文本写作软规划一起做。
