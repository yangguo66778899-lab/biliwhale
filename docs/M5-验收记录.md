## 3. 备份与恢复（新增）

- **格式**：自己实现的 store 模式 zip（零依赖），带 `manifest.json`（程序版本、配置版本、创建时间、是否含凭据）。
- **默认内容**：`config.json`、`state.json`、`quota.json`、`seen.json`、`feedback.json`、`replied.json`、`pending/replies.json`、
  `reports/`、`diaries/`、`archive/`、`runs/`、`chat/owner.jsonl`。**不含 `secrets.json`**（要带就 `--with-secrets`）。

## 4. 配置迁移（§7.14「安装后做配置 schema 迁移」）

- `src/config/migrate.ts`：`CURRENT_CONFIG_VERSION = 2`，迁移表按版本号递增，**只往前走、每步幂等**。
- v1→v2：补 `account.ownerMid/ownerName`、`app.updateUrl`，并提示「主人 UID 还没填」。
- 触发点：`ConfigService.load()`；迁移后立刻写回（保留 `.bak`），日志记「配置已从 v1 迁移到 v2」。
- 比程序更新的配置（装回旧版）：原样保留 + 提示，不猜。
- 测试：4 个迁移用例 + 1 个集成用例（磁盘上的 v1 配置 → 启动后变 v2）。

## 5. 检查更新（§7.14 首版）

- 配置项：`app.updateUrl`（留空 = 不检查）。远端返回 `{"version":"0.8.0","url":"…","notes":"…"}`。
- 比较规则：**只看主.次.修**（`0.7.0-M5` 与 `0.7.0` 视为同一版，避免自己给自己弹更新）。
- 行为：只提示 + 给下载地址；**不自动下载、不自动安装、不联网做心跳**。
- 入口：面板「关于 → 检查更新」、`/api/update/check`、`npm run update:check`。
- 测试：5 个用例（没配置/有新版本/同版本/远端缺字段/HTTP 500/非 http 地址）。

## 7. 7 天无人值守（§13）

`npm run soak`（加速时钟：7 天 × 每步 30 分钟 = 336 次 tick，真实耗时约 1 秒）：

```
日期        醒来  跑轮  报告  日记  错误
2026-11-01    3     3   ✓    ✓   0
2026-11-02    3     3   ✓    ✓   0
2026-11-03    3     3   ✓    ✓   0
2026-11-04    3     3   ✓    ✓   0
2026-11-05    3     3   ✓    ✓   0
2026-11-06    2     2   ✓    ✓   0
2026-11-07    3     3   ✓    ✓   0

合计：醒来 20 次，跑轮 20 次，7 天
```

断言（不通过就退出码 1）：

1. 每天唤醒 ≤ 3 次、跑轮 ≤ 3 次（硬上限）
2. 每天都有报告与两本日记
3. run 记录里没有错误
4. 第 4 天改配置（把早上窗口挪到 06:30）→ 5 秒内热更新生效，且调度器**重算**计划
5. 第 5 天暂停 → 当天少跑；恢复 → 接着跑（事件里能看到 `pause` / `resume`）
6. 暂停当天醒来次数 ≤ 2（暂停期间不跑）

## 8. 本轮修掉的问题

1. **配置改坏会静默回落默认值**：热更新时先 `validateOnly`，不合法就保留当前配置并报错。
   以前一个写坏的 `schedule` 会把窗口/开关全冲成默认值。
2. **热更新要等 1 秒**：daemon 里原来有一层 500ms `setTimeout`，ConfigWatcher 又有一层 debounce。
   现在是单层 debounce（500ms），并且加了 **5 秒 mtime 轮询兜底**——`fs.watch` 漏事件时也能生效。
3. **portable zip 打不出来**：自己写的 zip 遇到 `BiliWhale-x/` + 相对路径拼出双斜杠，被 zip-slip 校验拦下（好的一面：校验真的有用）。
4. **`dist/` 被编码不变式扫到**：构建产物不该参与源码约定，已排除。
5. **`backup list` 会在默认数据目录建配置**：改成只读 zip，不碰数据目录。

## 9. 需要你本人验证的部分（⏳）

我这边没法开一台干净虚拟机，也没法点「下一步」。下面三件事请你在真机上过一遍：

1. **干净虚拟机 5 分钟**：拷 zip 进去 → 解压 → `install.cmd` → 托盘开面板 → 扫码 + 填主人 UID + 填 key → 预演一轮。
   计时；顺便确认开始菜单里图标能启动、`--autostart` 后重启电脑会自己起托盘（不弹窗）。
2. **卸载后数据还在**：`uninstall.cmd` → 确认 `%APPDATA%\BiliWhale` 里的报告日记还在；再用安装包重装，数据能接上。
3. **升级一次**：留一份旧版 `install.cmd` 的包，做一次覆盖安装，确认日志里出现配置迁移记录、面板数据没丢。

## 10. 刻意没做（留后续）

- **真正的安装器 exe（Inno Setup）**：需要引入构建期工具链；现在用「便携包 + 脚本安装」，同样免管理员、可卸载。
  要做的话是 `packaging/` 里加一份 `.iss`，不影响内核。
- **自动更新**：只做「检查 + 提示 + 手动装」（§7.14 首版就这么写的）。
- **崩溃自愈 / 计划任务兜底**：M6。
- **代码签名**：没有证书，Windows 可能提示「未知发布者」；验收时按「更多信息 → 仍要运行」。
