> 对象：`审计报告.md`（16 个一级、41 个二级、46 个三级，均带 `文件:行号`）。
> 处理原则：**每条先核验再决定**。核验结论只有四种：
> **已修**（有代码 + 回归证据）、**部分修**（说明修到哪、剩什么）、**未修-理由**（真实但不适合现在改/需要真机）、
> **不成立**（按报告描述的现象不存在，或影响被放大）。
> 全部核验以**代码与实测**为准，不采信文档里的「已修好」。
> 基线：`npm run typecheck` 干净；`npm test` **376 个用例全绿**；夹具整轮可跑。
>
> **「状态」列按 `docs/AI-执行清单.md` §2 的口径**（只允许五个值）：
> `已修` / `暂缓(P0外)` / `待拍板` / `待真机` / `不改`。
> 「结论」说的是**核验结论**（事实），「状态」说的是**接下来怎么办**（排期）——两者不是一回事，
> 所以会有「结论=部分修、状态=暂缓(P0外)」这种行。

**最重要的 8 个修复**（都能指到具体行/测试）：

1. 私信分享的 TDZ 崩溃 + 它原来**整段绕过闸门**（现在走 `executeShares`，合并成一条，逐条记账）。

4. 写间隔被并发绕过（实测 250/116ms）→ 写请求改为**串行队列**，抖动恒定叠加。
5. 单实例锁「跑满 24 小时就失效」→ 心跳新鲜度优先于 24h 规则。
6. 托盘/安装/卸载脚本所有写请求没带 CSRF（全 403）→ 客户端补 `/api/session` + `x-csrf-token`，卸载实测能停内核。
7. 配置「损坏」被当成「不存在」→ 静默重置安全开关（dryRun 变 false）；现在区分 missing/corrupt/unreadable，且不写回默认值。
8. 心跳定时器没有 try/catch（一次写盘失败 = 进程静默死）→ 所有定时器回调包住，心跳失败记事件继续跑。
