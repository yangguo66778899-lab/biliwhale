## 3. 闸门（§10.1）

`gateShare()` 是纯函数，**所有拒绝理由都收集**（不是第一个不过就 return），因此报告能解释「为什么没发」。

实测（夹具 + dry-run 真跑一轮）：

```
> 看了 5 条，深读 3 条，挑中 2 条，分享 0 条（预演，未真的发）；本轮 6.2k token。
- 分享：预演（没真的发）
- 文案：@鲸鲸 这个结论我认，尤其是「只让它扩写要点」那条路线，比换个更聪明的工具管用。
- 没发：模型没给分享文案
- 分享：预演 1 条，没发 1 条
```

账本里同步落了一条 `status: "dry_run"` 的记录（含 `aid`、`content`、`contentHash`、幂等键），`counts.shared=0` —— **预演不占额度、不算分享**。

## 5. 需要你本人验证的部分（⏳）

我没有、也不会替你在真实账号上发任何东西。以下三件事需要你亲手做一次（都在面板里）：

1. **真发一条评论**：设置 → 分享 → 打开「允许对外分享」，安全 → 确认「一律预演」是关的 → 概览「跑一轮」。
   预期：报告里出现「分享：评论已发出（rpid …），复核通过」；账本 `quota.json` 里状态 `sent` 且带 `verifiedAt`。
2. **撞限额**：把 `share.dailyCap` 调成 1，再跑一轮。预期：报告写「没发：今日额度用完（1/1）」。
3. **审批一条**：需要有人在你的评论下回复（或者等 M4 的监听）。面板「扫描新回复」→ 出现草稿 → 点「发」。

如果第 1 步的 rpid 或复核出问题，把「日志 → 下载诊断包」发我，`quota.json` 与事件流里会有完整痕迹（不含 cookie）。

## 7. M3 期间修掉的问题

1. **每日写总量 off-by-one**：原写法在边界上会多发一条；改成 `writesToday + 本轮 + 1 > 上限`。
2. **「主人回复直发」在单账号下不可达**：自己回自己会在扫描阶段被跳过，`ownerDirect` 分支永远进不去——删掉那段假代码，留给 M4。
3. **手动删评论绕过了编排器**：面板直接调 `writer.deleteComment` 会绕过开关与凭据检查；收进 `orchestrator/manual.ts`，
   并加上「只认账本里自己发过的 rpid」。
4. **报告里分不清「闸门通过」与「真的发了」**：报告新增按执行结果渲染（已发/退出复核/预演/失败/没发），而不是只写闸门结论。

### 真机反馈后修掉的（0.4.1-M3）

5. **面板在浏览器里只剩空壳**：`<script src="/app.js">` 与 `<link href="/style.css">` 带不上 `?token=`，被 401 挡掉 →
   页面永远停在「连接中…」、点标签没反应。修法：用 token 打开页面时种 **HttpOnly + SameSite=Strict 会话 cookie**，
   子资源与 API 都认它；无凭据的浏览器导航改成说明页（不再是裸 JSON）。
   教训：M2 的测试只验了「带 token 取静态资源」，没有按浏览器的真实顺序（先开页面、再不带 token 取子资源）走过一遍。
6. **`index.html` 混进两处字面量 `` `n ``**：PowerShell 改 HTML 时把换行写成了字面量，标签栏多出一个 `` `n ``、两个 section 挤一行。
   已重写该文件，并加断言「HTML 里不许出现反引号」。
7. **面板 JS 没 token 就直接放弃**：改成优先用会话 cookie；只有 `/api/session` 真的失败才报错，并提示「从托盘重新打开」。

新增回归测试 `test/panel-assets.test.ts`（3 个用例）：打开页面拿 cookie → **不带 token** 取 `/app.js`、`/style.css` 必须 200
→ 伪造 cookie 拿不到数据 → 无凭据导航得说明页/API 得 401 → `index.html` 反引号检查。

### 又一批真机反馈后修掉的（0.4.2-M3）

8. **面板所有按钮都不响应**：`el()` 把 `onClick` 转事件名用了 `key.slice(2)` → `"Click"`（大写 C），
   而 `addEventListener` 对事件名大小写敏感 → 每个按钮都只渲染、不响应（用户点「扫码登录」没反应就是这个）。
   修法：`key.slice(2).toLowerCase()`。
9. **账号页要手点才出二维码**：现在没登录就自动生成；重复的「扫码登录」标题改成「二维码」、按钮改成「生成二维码」。
10. **交互层测试缺位**：新增 `test/ui-actions.test.ts`（5 例），给 DOM stub 装事件记录并**真的派发 click**，
    覆盖「进账号页自动出码 / 刷新二维码 / 粘 cookie / 概览两个运行按钮的 dryRun / 待审的发与不发」。

## 8. 刻意没做

- **收藏 / 私信 / 动态 / 点赞**：M4（不变式里已禁止提前出现）。

- **主人直发（ownerDirect）**：M4 双账号/监听场景再做。
- **审批草稿编辑**：M3 只能「发 / 不发 / 预演」，改文案留 M4（面板编辑 + 重新生成）。
- **真实发送**：见 §5，等你的号。
