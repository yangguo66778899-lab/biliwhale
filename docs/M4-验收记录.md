## 1. M4 完成标志（§15）

|---|---|---|

## 2. 各能力对照（§10.2 / §7.9 / §7.11）

| 能力 | 实现要点 | 证据 |
|---|---|---|
| 收藏（默认开） | 理由 ≥6 字；同类已 ≥2 条必须说明「比它们好在哪」；每天 ≤3；同视频 30 天；只收藏深读过的；发完查收藏夹复核（两次），失败标 `unverified` 不重试 | `canFavorite()` 的 8 条断言 + 执行器的 5 个用例 |
| 点赞（默认关） | 只点深读过的；每天 ≤5；和总写开关/急停/风控共用 | 「点赞」用例：默认关 0 请求，打开后 1 请求且记账 |
| 动态（默认关） | 一轮里**从不**自动发；必须 `requireConfirm`；每天 ≤1 | 「动态」用例：关了 0 请求；`confirm:false` 被拒；确认后 1 请求 |
| 私信分享（`share.via='dm'`） | 一轮合并成**一条**、≤500 字、最多 5 条视频；占分享额度 | 「私信分享」两个用例（预演 0 请求；真发 1 请求） |
| 私聊通知（默认关） | 摘要（超长注明去面板）、公开日记（≤500 分段、最多 5 段）、视频信息（标题+链接+简介≤200+已有理解，总长 ≤500，超长先砍简介）；三个子开关独立；只发今天上下文里的 BV | 4 个用例（子开关 / 白名单 / 渠道关 / 文案截断） |
| 评论/@ 监听（默认关） | 间隔 ≥60s + 0–20% 抖动，空闲退避到 15 分钟；游标 `lastCommentSeenAt`；**首次只建基线**；陌生人 → 待审队列 | 「首次只建基线」「第二次进队列」「关着不请求」「间隔边界」4 个用例 |
| 私信监听 + 聊天（默认关） | 只拉会话列表；没新消息不拉消息、不调模型（零 token）；只处理主人会话；每条最多回 1 条（msgKey 去重）；≤20 条/小时；撞风控停 30 分钟；上下文只有人设+最近 N 条+今天公开日记+报告摘要+今天的 BV（不含字幕）；附件只允许公开日记与白名单 BV；拒绝清单有代码兜底；`chat/owner.jsonl` 保留 30 天、面板可清空 | 11 个用例（含「不调工具/不改配置」「去重」「小时上限」「附件白名单」「拒绝兜底」「上下文不含字幕」） |

## 3. 面板「私聊」页（§7.10）

| 项 | 证据 |
|---|---|
| 状态区 | 监听开关、聊天开关、发给谁（mid）、通知推送与三个子开关、最近一小时条数 |
| 手动发送 | 测试消息（回车发）/ 今天的公开日记 / 今天的视频信息；都走 `/api/dm/send` |
| 视频信息防呆 | 面板先取最近报告里的第一个 BV；服务端再校验「是否在今天的上下文里」，不在就 409：「BV1unknown1 不在今天的上下文里」 |
| 记录 | 聊天记录倒序可看，一键清空（二次确认） |

实测（夹具 + `dryRun`）：

```
dm 状态     {"enabled":false,"chat":true,"receiver":4242,"notifyEnabled":true,"maxPerHour":20}
手动发送     200 {"ok":true,"message":"预演：给 4242 发一条私信（6 字）（未发送）"}
陌生 BV      409 {"ok":false,"message":"BV1unknown1 不在今天的上下文里（只发今天出现过的视频）"}
监听一次     200 {"skipped":["评论监听关着","私信监听关着"]}
```

把监听打开后（`PUT /api/config`，热更新 1.2s 生效）：

```
dm.enabled   true
listen/now   200 {"comment":{"baseline":true,"seen":0,"created":0,"skipped":["读「回复我的」失败：夹具里没有这条请求…"]},
                  "dm":{"handled":0,"skipped":["读会话列表失败：夹具里没有这条请求…"]}}
```

——说明监听**真的去读了**（夹具里没有这两个接口，所以是干净失败，不是静默不干活）。

## 5. 需要你本人验证的部分（⏳）

我依然没有、也不会替你在真账号上发任何东西。下面这些需要你亲手点一次（都在面板里）：

1. **收藏**：设置 → 收藏（默认已开）→ 概览「跑一轮」。预期：报告里出现「已收藏 BV…（复核通过）」，`quota.json` 有 `fav/sent`。
2. **私信**：设置 → 监听与回复 → 打开「监听私信」，账号页确认已登录；私聊页点「发一条测试消息」。
   预期：手机 B 站收到一条私信；`chat/owner.jsonl` 里出现一行。
   > ⚠️ 私信与动态的接口形状是照公开实现写的，**这是 M4 最可能出问题的一处**。失败的话把诊断包发我。
3. **聊天**：用你的号给这个账号发一条私信。预期：它回你一条（≤500 字），面板「私聊」里能看记录。
4. **评论监听**：设置 → 监听与回复 → 打开「评论与 @ 监听」，然后在任意视频下回复它的一条评论。
   预期：面板「待审」出现一条草稿（第一次监听只建基线，不会把旧消息当新的）。

## 7. M4 期间修掉的问题

1. **`index.html` 里出现 `\`n` 字面量**：PowerShell 拼 HTML 时把换行当字面量写进文件，标签挤成一行；改用 Node 脚本修，并加了「面板不引外链/无内联脚本」的不变式。
2. **手动预演也写了聊天记录**：`dryRun` 下不该在 `chat/owner.jsonl` 里留一条没真正发出的消息。
