## 4. 真接口验证中修掉的 bug（夹具测不出来）

1. **匿名 `nav` 返回 `code:-101` 但 `data` 里仍带 `wbi_img`**：原实现把整包当错误丢掉，导致匿名连签名材料都拿不到、搜索直接失败。现在 nav 走「不解包」通道，`-101` 视为未登录。
2. **签名器在串行队列内部取 nav → 队列自锁**：脚本卡死在搜索那步。现在签名在入队前完成。
3. **同一秒跑两轮覆盖运行记录**：id 只有秒级时间戳，连点两次会丢事务日志。现在冲突加后缀。

## 5. 首次真实模型跑通（2026-10-21 14:47，用户提供 key）

这一轮是 M0 停止条件的判据，产物在用户指定的数据目录（`--data-dir`）里。

| 项 | 实测 |
|---|---|
| run id | `2026-10-21T14-47-33`，`status: ok`，耗时 120s |
| 模型 | 配置 `deepseek-flash` → 实际 `deepseek-flash`（自动发现生效） |
| 计数 | 候选 30 → 初筛 10 → 深读 3 → 挑中 1 → 分享 0（M0 只读） |
| token | 输入 19394 / 输出 5065 / 缓存命中 1408（上下文缓存确实生效） |
| 登录态 | 预检读到真实昵称（说明 cookie 有效） |
| 相位耗时 | 候选 11s / 轻读 72s / 初筛 11s / 深读 4s / 决策写作 21s |

**质量判断（M0 停止条件）**：通过。

- 公开日记不是汇报腔：它写了 1986 年七巧板实验「40 多个词掉到 8 个、换搭档涨回 30 多个」，写了评论区 904 赞那条在讲什么，还写了自己「本来是带着偏见点进去的」。
- 私人日记有真偏好校准：承认这条内容密度高但**和用户平时的 AI 工具/猫咪/鬼畜剪辑不对路**，并写下「今天这个选择本身就暴露了我容易被争议标题吸引」，给出下次的做法。
- 跳过理由具体到内容（哪一段开始念口播、评论区在聊什么），不是「质量一般」。

**复检这一轮产物后修的 4 处**（都已在本次提交里）：

1. `model.calls` 记成 1（深读相位名叫 `decide`，统计却按 `deep` 过滤）→ 改为累计每次 agent loop 的真实 `steps`，`state.budget.calls` 一起修正。
2. 日报「今天的账」混进 `M0 不抽帧`、`M0 只读`、`登录态正常` 这类排障信息 → 拆出「### 运行备注（排障用）」。
3. 跳过备注出现句末「，」没收干净 → 渲染时清理句末标点。
4. `report_md` 没进日报（且提示词示例是空字符串，模型照着给空）→ 现在写进每轮「### 这一轮」小节，提示词明确要求 2–4 段。

另外事件流原来一轮只有 1 行，现在补成 `candidates / screen / deepread / decision / round` 五条，便于排障与将来面板的时间线。

## 6. 已知限制

- 字幕需要登录 cookie（匿名实测 0 条轨）；没 cookie 时报告会明说「字幕拿不到」，不要误判成视频没字幕。
- 代理未接（`app.proxy` 字段与校验已就位，链路留 M5）。
- 不抽帧（ffmpeg 只在体检里检查）。
- 轻读相位约 72s（10 条 × 4 个串行请求）。串行是刻意的（B 站 412 的教训），要更快只能减少 `screenLimit` 或缓存字幕。
