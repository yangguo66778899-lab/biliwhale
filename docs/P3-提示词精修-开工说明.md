## 2. 逐条怎么做

### 2.1 视角与人设（第 5、6 点）—— 先定这一层，其余都挂在它下面

`system.md` 改成三段，**互不串味**：

```md
## 一、你是谁（人设，会变）
{人设注入：名字、称呼、自称、语气、喜恶}
→ 只负责「听起来像谁」。不负责场景，也不负责任务。

## 二、你现在的身份（场景，固定）
你是一个刚刷完 B 站的人。你看视频是为了自己看，顺手把觉得有意思的告诉一个朋友。
- 不是客服，不是助手，不是运营，不是汇报机器人。
- 没有人给你布置任务，你不需要「总结」或「交付」。
- 你说话的对象只有一个：那个朋友（主人）。

## 三、你手上的活（任务，随相位变）
- 写评论：你在视频下面看到一个想回一句的东西。
- 写日记：你晚上想起来今天看了什么。
- 聊天：朋友发消息给你。
```

**为什么要分开**（工程上可行）：人设文件只替换「一」；「二」写在 system.md 里由代码拼；「三」由各相位 prompt 给。这样人设换成「千金大小姐」或「乖巧女仆」，**场景角色不变**——她依旧是观众。

**报告 vs 日记的边界**（第 2 点）写进 system.md：
- 报告是给系统看的记录（挑中/跳过/账），**由代码生成**；
- 日记是给人看的感受，**不许出现**：`我选了 N 篇`、`评分 XX/20`、`阈值`、`候选 N 条`、`分享 N 条`、`收藏`、`token`。
- 也不许写「今天共看了 X 条」——那是账，不是感受。

### 2.2 字数的真实语义（第 4 点）

现在提示词写「≤800 字」，模型的默认理解是「尽量接近 800」。改成：

> 上限 N 字，**不是目标**。一句话、十个字，只要把话说完了，就是合格的。
> 想写长，得有值得写长的东西（具体细节多、有转折）；凑字数会让它看起来像报告。

并在示例里给一条**极短**的评论（比如 12 个字）和一条 40 字的，让「短」看起来是允许的。
自检只查上限，不查下限。

**标点**：评论/聊天默认**不加句号**（问号、省略号、感叹号可以有）；日记保留正常标点。
注意：这是「默认」，不是禁用——该加时仍可加。

### 2.3 不 @ 的评论（第 3 点，唯一的功能新增）

现状：分享=评论+@主人，只能有一条。你要的是**另一步**：这条视频想不想单发一句评论（不 @ 任何人）。

- 配置：`share.comment.plain`（默认 **false**，P1 规则：要有一句人话说明）。
- 模型输出：`selected[].comment = { want: boolean, text: string }`（与 `share` 并列，互不影响）。
- 判定标准（写进 prompt）：「这句话我有没有想让评论区其他人也看到」——有就写，没有就不写。
- 执行：仍然只走 `share.ts`，仍然过同一道闸门（写开关/急停/额度/冷却/幂等/每日写上限）。
- 报告：「评论：发了/没发（原因）」一行；被拒时同样写「本来会发：…」。
- 额度：「不 @ 评论」与「@ 分享」**共用** `share.dailyCap`，但各自记账（避免一轮全发出去）。
- 不做：不进 AI 自动流程之外的任何地方（仍是一轮内、仍受闸门）。

### 2.4 B 站表情（第 7 点）

B 站评论/聊天支持文本表情码（`[doge]`、`[星星眼]`…）。**表情是评论区的语言，日记里不用**（日记是私人文字）。

精简白名单（16 个，覆盖常用情绪；要加减你定）：

`[doge] [笑哭] [妙啊] [捂脸] [吃瓜] [星星眼] [给心心] [大笑] [思考] [辣眼睛] [藏狐] [支持] [打call] [嗑瓜子] [喜极而泣] [调皮]`

规则（写进 prompt + 自检）：
- 一条最多 **1–2 个**；情绪对不上就**别用**，不要开头/结尾硬塞；
- 只在评论与聊天里用；@ 评论同样可以；
- 自检：评论里表情数 ≤2、日记里出现任何 `[xxx]` 就重写一次；
- **真机验证项**：B 站评论接口是否原样接受并在客户端渲染（需要你发一条看）。

### 2.5 工作方法：prompt lab（第 1 点）

不做「跑一轮完整流程」来测提示词——那样变量太多、一天只能试几次。改成：

```
npm run prompt:lab -- --times 3 --videos 3
```

- 输入：`fixtures/prompt-lab/*.json`（固定材料：标题/UP/时长/简介/字幕/热评；**不用真串取数**）。
- 过程：对每条视频用**真实的 buildDeepPrompt** 组装，调模型 `--times` 轮；只解析「写评论 + 两本日记 + 通知」这几项，
  其余（分享/收藏/点赞）全部跳过，**不执行任何写操作、不落正式报告**。
- 输出：`.run/prompt-lab/<时间>/<bvid>/run-<n>/{comment.md, diary-public.md, diary-private.md, raw.json}`
  外加一份 `index.md`：每条评论的字数、有没有句号、表情数、是否 @，方便你一眼扫。
- 用途：每改一版提示词就跑一遍，你只需要在 `index.md` 上批注「这条像人 / 这条是报告」。
- 无 key 时用 `--fixtures`（脚本化模型）跑通流程，验证工具本身。

## 5. 下一轮的做法（顺序固定）

1. **先做尺子**：`prompt-lab` + 3 条固定材料 + `index.md` 汇总。用 fixtures 模型跑通，证明工具能用。
2. **再改文本**：`system.md` 三层结构 → `buildDeepPrompt`（字数语义/标点/表情）→ `chat.md` 抽出。
3. **再上自检**：10–12 项，重写一次；不合规时的提示词要写清「哪一项、为什么」。
4. **然后跑 lab**：3 条视频 × 3 轮，你在 `index.md` 上批注；我按批注改，再跑一轮。
5. **最后定稿**：文档（本文件 + 清单 §7.12）+ 用例 + CHANGELOG。

## 6. 风险与回滚

- **表情**：接口不接受/乱码 → 白名单清空即可（配置一个开关，不加代码）。
- **不加句号**：有人觉得轻浮 → 改 prompt 一行就能回退。
- **不 @ 评论**：可能被判刷屏 → 默认关、共用额度、单独记账，随时能关。
- **prompt lab**：只读，不写任何远端内容；`--fixtures` 不需要 key。
