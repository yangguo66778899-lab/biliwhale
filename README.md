BiliWhale
=========

一个常驻 Windows 的 B 站「养鱼」程序内核：它按自己的作息醒来，去 B 站读视频、判断值不值得，
写一份日报和两本日记，把真正值得的分享给你。

只调用 DeepSeek；不依赖 Python、不依赖任何 agent 宿主、不依赖数据库。

本仓库当前状态：**M3（分享 + 闸门）已完成**。M0 让「一轮」跑通（真模型 `deepseek-flash`、真 B 站、30→10→3→挑中 1），
M1 把它装进常驻进程（到点自己醒、托盘可控、单实例、开机自启），
M2 给了它一个只有你自己能打开的本地面板（配置、扫码登录、报告与日记、体检与诊断包），
M3 给了它**唯一一种写能力：在视频下发一条评论 @ 你**——而且默认关着，闸门、幂等、复核、风控、审批队列都在代码里。

**写能力只有「评论 @」一种，且默认关闭**（`share.enabled=false`；`safety.dryRun` 打开时只打印不发送）。
收藏 / 私信 / 动态 / 点赞仍然**不存在**，那是 M4。

- 常驻跑起来：`npm run serve`（或 `node src/cli.ts serve`），它会打印面板地址（`http://127.0.0.1:<port>/?token=…`）
- 面板：概览 / 设置 / 账号 / 报告 / 日记 / **待审** / 日志 / 关于；离线可用，不引 CDN
- 托盘：`npm run tray:build` → `shell\BiliWhaleTray.exe`，右键可「打开面板」「现在跑一轮」「暂停」
- 离线验证（不联网、不花钱、不需要凭据）：`npm run m0:offline`
- 真接口验证：`npm run smoke:bili`（只读）与 `npm run m0:live-read`（真 B 站数据 + 占位模型）
- 真实跑一轮：设 `BILIWHALE_API_KEY`（可选 `BILIWHALE_COOKIE`）后 `node src/cli.ts run --now --dry`
- **想让它真的发评论**：面板「设置 → 分享」打开「允许对外分享」，并确认「安全 → 一律预演」是关的；
  先用「预演一轮」看文案与闸门结论，再让它真发。

完整需求与验收标准见 [`独立程序-需求文档.md`](./独立程序-需求文档.md)（v0.5），

   分享闸门（每日上限 / 同视频冷却 / 只从深读过里挑 / 发后复核）、收藏与分享并列、沉默衰减、

**说明（请务必读完）：**

- 本项目**自用为主**，没有针对通用场景做适配：默认单人单账号、Windows 优先、中文界面。
- 本项目**重写了模块边界与数据结构**，并且明确删掉了参考项目里的若干做法（见需求文档 §3 的
  「不要照抄」清单：宿主耦合、`spawn dsh`、Python/MCP、配置双写、用报告行数算配额等）。
- 本项目**没有直接复制上述两个项目的代码**。B 站接口（搜索、字幕、评论、WBI 签名等）是按公开的
  接口行为自行实现的；`NOTICE` 里记录了「如果将来引入它们的代码，该按什么许可证处理」。
- 许可证：MIT（见 `LICENSE`）。参考项目的版权归各自作者所有。

快速开始
--------

要求：Windows 10/11，Node.js ≥ 22.6（开发与运行都是原生 TS，无需构建步骤）。

```bash
# 1) 安装开发依赖（只有 typescript 和 @types/node，运行时零依赖）
npm install

# 2) 体检：目录/凭据/网络/模型/单实例锁/控制接口/心跳/自启/托盘/ffmpeg
node src/cli.ts doctor

# 3) 常驻跑起来（作息 + 本地控制接口）；关掉这个终端就停了
node src/cli.ts serve
#   面板地址会打印出来（形如 http://127.0.0.1:8787/?token=...），也可以从 runtime.json 读

# 4) 托盘（可选，但常驻推荐）：编译后直接运行，会自动接管已在跑的内核
npm run tray:build
shell\BiliWhaleTray.exe

# 5) 手动跑一轮（不常驻也能用；只读，不产生任何远端写操作）
node src/cli.ts run --now --dry

# 6) 验证
npm test              # 212 个用例：写层/闸门/幂等/复核/风控/审批/面板/登录/二维码/调度/守护进程/离线整轮
npm run m0:offline    # 夹具整轮：不联网、不需要凭据
npm run m0:live-read  # 真实 B 站数据 + 占位模型（不代表模型质量）
npm run smoke:bili    # 真 B 站只读冒烟：WBI / 搜索 / 视频 / 评论 / 字幕轨
```

### 面板（M2 起，M3 加了「待审」）

`serve` 起来后打开它打印的地址（`http://127.0.0.1:<port>/?token=…`），或从托盘右键「打开面板」：

| 页 | 内容 |
|---|---|
| 概览 | 状态、下一次唤醒、今日额度与花费、最近一轮；预演 / 跑一轮 / 暂停恢复；体检表 |
| 设置 | 20 组、96 个字段，全部来自 `config/spec.ts` 的元数据；保存即生效，可校验、导出、导入、恢复默认 |
| 账号 | 扫码登录（二维码 + 2 秒轮询）、cookie 粘贴、复核、退出（只清本机）、UID 与凭据指纹 |
| 报告 / 日记 | 按日期列表 + Markdown 预览（日记分「给你看的」「给自己看的」两本，可按内容搜索） |
| 待审 | 陌生人回复的草稿：谁、原话、拟回复；「发 / 预演 / 不发」，可手动「扫描新回复」 |
| 日志 | 事件流（级别过滤）+ 下载脱敏诊断包 |
| 关于 | 版本、数据目录、模型、今日预算、快速操作 |

面板的三个前提：只绑 `127.0.0.1`；所有请求要凭据；写操作还要 `x-csrf-token`（页面自动处理）。

**怎么打开**（三选一，后两种最省事）：

- 托盘右键 → **打开面板**
- 用 `serve` 打印出来的完整地址（带 `?token=…`）
- 从 `runtime.json` 的 `url` 字段复制

**为什么第一次必须带 token**：内核用它认人。用 token 打开后，内核会给这个浏览器种一个
`HttpOnly + SameSite=Strict` 的会话 cookie（7 天、只在本次进程内有效），此后刷新、子资源、API 都靠它，
地址栏里的 token 会被页面自动抹掉（免得留在浏览历史里）。**内核一重启，旧 cookie 就失效**——从托盘再点一次即可。

顺手提醒：如果面板打开是空白/「连接中…」不动，先 `Ctrl+F5` 硬刷新一次；还不行就看命令行窗口有没有报 401。

### 常驻形态（M1）

```
托盘(BiliWhaleTray.exe) ──HTTP+token──> 内核(node src/cli.ts serve)
        │                                   │
        │  读 runtime.json（端口+token）      ├─ scheduler：到点自己醒
        └─ 菜单：状态/面板/跑一轮/暂停/自启    ├─ 本地控制接口 127.0.0.1
                                              ├─ heartbeat.json（壳判断存活）
                                              └─ instance.lock（单实例）
```

- 内核没起来时，点托盘「启动内核」会用 `node src/cli.ts serve` 拉起来（需要 PATH 里有 node）。
- 开机自启：优先写 `HKCU\...\Run`；受限环境自动回落 Startup 文件夹的 `BiliWhale.cmd`（两种都能在托盘里开关）。
- 关掉终端里的 `serve` 就等于停掉内核；托盘会显示「内核没在跑」。
- `--data-dir` 可以覆盖数据目录（开发/多套数据时用），托盘也支持同名参数。

> `--fixtures` 走的是 `fixtures/bili/*`（B 站响应）与 `fixtures/llm/*`（模型输出），
> 与 `npm test` 里的 golden 用例共用同一套夹具；CI 不需要网络与真实凭据。
> `--mock-model` 用真实 B 站、占位模型；它证明的是「链路通」，不是「判断好」。

凭据（不进仓库、不进日志）：

- **DeepSeek key（必须有，否则跑不了任何一轮——「预演」也要真调模型）**：
  面板 → **设置** → 最上面的「DeepSeek key」卡片，粘进去点「保存并验证」。
  会先用新 key 拉一次 `/models`：**验过了才落盘**，填错不会覆盖原来能用的 key；成功后会顺手自动发现模型。
  也可以用环境变量 `BILIWHALE_API_KEY`（它优先级更高，设了之后面板里存的不生效），或直接写 `<data>/secrets.json`。
- B 站：面板「账号」页扫码（推荐），或粘 `SESSDATA=...; bili_jct=...; buvid3=...`，或环境变量 `BILIWHALE_COOKIE`。没登录也能跑，但拿不到字幕，几乎每条都会被「无字幕」跳过。

面板改配置写的是 `<data>/config.json`（原子写 + `.bak`）；凭据永远单独放 `secrets.json`，导出配置与诊断包都不会带上它们，面板也只显示指纹（如 `sk-…a1b2`）。

数据目录（Windows 标准位置，全新开始，不读任何旧数据）：

| 用途 | 路径 |
|---|---|
| 持久数据（配置 / 凭据 / 账本 / 报告 / 日记） | `%APPDATA%\BiliWhale` |
| 日志 / 缓存 / 心跳 | `%LOCALAPPDATA%\BiliWhale` |

调试时可用 `--data-dir <path>` 覆盖，或用 `--fixtures` 走离线夹具（不碰真实 B 站、不调用真模型）。

安全边界（第一阶段就成立，不靠后面补）
--------------------------------------

- 所有对外发言类写操作（评论 / 私信 / 动态 / 点赞）**默认关闭**；收藏默认开但可关。
- **M3 起有且只有一种写能力：评论 @**（`share.enabled` 默认 `false`）。写之前必须过闸门：
  开关 / 分数 / 只从深读过里挑 / 今日额度 / 同视频 7 天冷却 / 沉默衰减 / 风控冷却；
  幂等键（内容哈希）命中就拒绝；发后复核 3 次，失败标 `unverified` 且**不自动重发**；
  撞风控立即停手 + 冷却。私信 / 收藏 / 动态 / 点赞在 M4 之前**代码里不存在**（有不变式测试守着）。
- 陌生人回复**一律走审批**（面板「待审」页），7 天没处理自动作废。
- 登录凭据只存 `secrets.json`，永不回显、永不进日志（统一 redact）；导出配置与诊断包都不带凭据。
- 不刷量、不批量、不绕过风控；B 站请求全部串行，带最小间隔与抖动（写间隔 5s + 抖动）。
- 本地面板只绑 `127.0.0.1`，所有接口要 token（在 `runtime.json` 里，权限 600），并校验 Host；
  写操作还要 CSRF token，页面带 CSP（无内联脚本、无外链）。

目录结构
--------

```
src/
├── cli.ts              # 命令行入口（run / serve / doctor / config）
├── bootstrap.ts        # 装配：配置+账本+B站客户端+写层+模型客户端（CLI 与守护进程共用）
├── doctor.ts           # 体检（CLI 与面板共用一份）
├── diagnostics.ts      # 脱敏诊断包
├── daemon/             # 守护进程：单实例、调度循环、心跳、优雅退出；api.ts = 面板接口实现
├── scheduler/          # 生物钟：计划生成（纯函数）+ tick 判定
├── lifecycle/          # 单实例锁、runtime.json / 心跳、开机自启
├── http/               # 本地控制接口 + 静态资源服务（server.ts）
├── ui/                 # 面板静态资源（原生 JS/CSS，无构建、无 CDN）
├── account/            # 扫码登录 + cookie 粘贴 + 登录态复核
├── qr/                 # 二维码编码器（自己写，零依赖，外部参照对拍过）
├── config/             # 配置 schema、默认值、校验、原子读写、面板元数据（describe.ts）；secrets 独立
├── state/              # state/seen/quota/feedback/runs + pending/replied 账本（原子写）
├── orchestrator/       # 一轮的相位编排、跳过分支、闸门、分享执行、待审队列、手动写、落盘
├── agent/              # prompt 组装、工具装配、工具循环、输出校验
├── llm/                # DeepSeek 适配 + 模型发现
├── bili/               # B 站接口：http（串行限速）/ wbi（签名）/ api（读映射）/ write（写：评论）
├── dev/                # 离线夹具栈与占位模型（--fixtures / --mock-model 与测试用）
├── prompts/            # 内置 system.md / charter.md / 默认人设
└── shared/             # 类型、日志（脱敏）、原子写、时间、错误分类
shell/BiliWhaleTray.cs  # C# 5 托盘（源码入库，exe 由 npm run tray:build 生成）
scripts/                # smoke-bili.ts（真接口只读冒烟）、smoke-panel.mts、build-tray.ps1
test/                   # 单元 + 集成（212 个用例，含二维码对拍与面板渲染）
fixtures/               # 离线夹具（B 站响应、模型输出）
docs/                   # 架构说明、B 站接口规格、M0/M1/M2/M3 验收记录
```

已知限制（M3 阶段）
--------------------

- **检查更新与反馈入口还没做**：需要远端仓库地址与打包形态，留 M5（面板「关于」页只有版本/目录/许可证）。
- **崩溃自愈还没做**：内核挂了不会自动重启（文档要求「壳/计划任务负责重启」）。托盘只会显示「内核没在跑」，重启退避留 M5/M6。
- **托盘要自己编译**：`npm run tray:build`（用 .NET Framework 自带 csc，不需要 SDK）；没编译时 `doctor` 会提示。
- **真实发送还没在你的账号上验过**：写层与闸门有 32 个测试（假传输层），闸门/幂等/复核/风控都跑通了；
  但「真发一条评论」需要你的号，见 [`docs/M3-验收记录.md`](./docs/M3-验收记录.md) §5。默认是关的，不会自己发。
- **只有评论这一种写**：私信/收藏/动态/点赞在 M4；面板里这些配置项目前只是配置。
- **监听循环在 M4**：M3 的待审队列由「本轮分享后的回复扫描」和面板「扫描新回复」喂；没有常驻监听。
- **字幕需要登录**：匿名请求拿不到字幕轨（实测 0 条），所以不带 cookie 时的「因无字幕跳过」是预期，不代表视频真没字幕。
- **代理还没接**：`app.proxy` 字段与校验已就位，实际链路待 M5 统一接（Node 24 的 env proxy 方案）。
- **不抽帧**：ffmpeg 只在体检里检查，`media.frames` 目前不生效。
- **日报由代码骨架 + 模型正文组成**：每轮的「### 这一轮」由模型写（`report_md`），「挑中的 / 看过的 / 今天的账」由代码生成；排障信息单独放在「### 运行备注（排障用）」。

后续里程碑（见需求文档 §15）：M4 次要写 + 监听/聊天，M5 打包，M6 硬化。
